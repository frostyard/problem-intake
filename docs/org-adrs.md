# Org-wide decisions (frostyard/core ADRs)

Some conventions are decided at org level. They are ADRs in
[frostyard/core](https://github.com/frostyard/core/tree/main/docs/adr).

These ADRs bind this repository. The list below says what each one binds here,
and where it lives in this repository.

## Baseline decisions

- [ADR-0018 — Org-wide agent instruction and knowledge surfaces](https://github.com/frostyard/core/blob/main/docs/adr/0018-org-wide-agent-instruction-and-knowledge-surfaces.md) — `AGENTS.md` is the canonical instruction file; `.cursorrules`, `CLAUDE.md`, `GEMINI.md` and `.github/copilot-instructions.md` are symlinks to it. Durable corrections go in the append-only inbox ([`.memory/README.md`](../.memory/README.md)).
- [ADR-0019 — Repository governance as machine-readable policy with risk tiers](https://github.com/frostyard/core/blob/main/docs/adr/0019-governance-as-code-and-risk-tiers.md) — every pull request declares a risk tier in the risk tier section of [`.github/pull_request_template.md`](../.github/pull_request_template.md), and [`policies/agent-governance.json`](../policies/agent-governance.json) holds the protected boundaries.
- [ADR-0021 — SHA-pinned actions and least-privilege CI workflows](https://github.com/frostyard/core/blob/main/docs/adr/0021-sha-pinned-actions-and-least-privilege-ci.md) — the workflows in [`.github/workflows/`](../.github/workflows/) pin every action to a full SHA with the version in a comment, set `permissions: {}`, and set `persist-credentials: false`; core's reusable workflow has no release tags, so its comment names `frostyard/core main` and the commit date.
- [ADR-0025 — One docs/ tree per repository, in core's four-category shape](https://github.com/frostyard/core/blob/main/docs/adr/0025-consolidate-repository-docs-into-docs.md) — all documentation lives in this [`docs/`](README.md) tree, in 4 categories (ADR, design, specs, plans), each with a `TEMPLATE.md`, plus the runbooks in `runbook/`.
- [ADR-0029 — ACMM conformance via canonical aliases](https://github.com/frostyard/core/blob/main/docs/adr/0029-acmm-conformance-via-canonical-aliases.md) — the tool paths are alias symlinks: `.claude/skills` is a symlink to `../.agents/skills`.
- [ADR-0040 — Publish the repository settings contract](https://github.com/frostyard/core/blob/main/docs/adr/0040-publish-the-repository-settings-contract.md) — [`SECURITY.md`](../SECURITY.md) states the support policy, and private vulnerability reporting is on for this repository.
- [ADR-0043 — Pin repository tools in mise and name the verify gate](https://github.com/frostyard/core/blob/main/docs/adr/0043-pin-repository-tools-in-mise-and-name-the-verify-gate.md) — [`mise.toml`](../mise.toml) and [`mise.lock`](../mise.lock) pin Node 24, the only tool the gate needs; `make verify` is the verify gate.
- [ADR-0044 — Expose the make gate triad in every repository](https://github.com/frostyard/core/blob/main/docs/adr/0044-expose-the-make-gate-triad-in-every-repository.md) — the [`Makefile`](../Makefile) has the `verify`, `check` and `ci` targets.
- [ADR-0051 — ADRs state facts only, not the process that produced them](https://github.com/frostyard/core/blob/main/docs/adr/0051-adrs-state-facts-not-process.md) — the ADRs in [`adr/`](adr/) state facts only.
- [ADR-0068 — Label pull requests that touch high-risk paths](https://github.com/frostyard/core/blob/main/docs/adr/0068-label-pull-requests-that-touch-high-risk-paths.md) — [`risk-paths.json`](../.github/risk-paths.json) lists the high-risk paths, and the PR triage caller ([`risk-paths-caller.yml`](../.github/workflows/risk-paths-caller.yml), core's `pr-triage` workflow) adds the `risk:high` label.
- [ADR-0069 — Report problems local-first, opt-in, with one sender per host](https://github.com/frostyard/core/blob/main/docs/adr/0069-report-problems-local-first-opt-in-with-one-sender-per-host.md) — this repository is the intake of those reports: the Worker at `https://report.frostyard.org` validates each report, strips the client address and forwards it to GlitchTip; [`schema/v1.json`](../schema/v1.json) is a byte copy of core's schema.
- [ADR-0071 — Hold every code repository to one baseline](https://github.com/frostyard/core/blob/main/docs/adr/0071-hold-every-code-repository-to-one-baseline.md) — every code repository carries the baseline checklist ([spec](https://github.com/frostyard/core/blob/main/docs/specs/repository-baseline.md)). It has a [`LICENSE`](../LICENSE), a [Dependabot config](../.github/dependabot.yml), and a [`ci.yml`](../.github/workflows/ci.yml) that runs `make ci`. It has no `CODEOWNERS`.
- [ADR-0072 — Write every README to one standard](https://github.com/frostyard/core/blob/main/docs/adr/0072-write-every-readme-to-one-standard.md) — the root [`README.md`](../README.md) declares the kind `service` and is checked by core's `frostyard-readme` checker.
- [ADR-0073 — Let CI run the `make ci` targets as separate jobs](https://github.com/frostyard/core/blob/main/docs/adr/0073-let-ci-run-the-make-ci-targets-as-separate-jobs.md) — [`ci.yml`](../.github/workflows/ci.yml) runs `make ci` in 1 job, `ci`, which is the required check.
- [ADR-0074 — Publish verified fault records as public issues in the owner repository](https://github.com/frostyard/core/blob/main/docs/adr/0074-publish-verified-fault-records-as-public-issues.md) — the triage job in [`scripts/triage/`](../scripts/triage/) opens 1 public GitHub issue with the label `problem-report` for each verified problem key, holding only the closed list of fields of [`docs/specs/triage.md`](specs/triage.md), each value checked against public source. It amends ADR-0069 in part; [`triage/`](../triage/) holds its routes, cutoff and allowlists, and [ADR-0006](adr/0006-a-triage-job-files-verified-problems-as-public-issues.md) records the choice.
- [ADR-0076 — Require status checks on every default branch](https://github.com/frostyard/core/blob/main/docs/adr/0076-require-status-checks-on-every-default-branch.md) — a merge to `main` needs the required status checks, the job `ci` among them, to pass; the ruleset that names them is a repository setting, not a file in this tree.
- [ADR-0077 — Bind `ready-for-human` to the head commit](https://github.com/frostyard/core/blob/main/docs/adr/0077-bind-ready-for-human-to-the-head-commit.md) — the label says the review passed at the PR head. Core's `pr-triage` workflow removes it when the head commit moves, so a new push must earn it again.
- [ADR-0078 — Sort pull requests by levels L1 to L4](https://github.com/frostyard/core/blob/main/docs/adr/0078-sort-pull-requests-by-levels-l1-to-l4.md) — [`risk-paths.json`](../.github/risk-paths.json) is at schema version 2: each glob has a level, and the workflow adds 1 `level:L1` to `level:L4` label, plus `risk:high` at L1 and L2. The boundary kinds of [`agent-governance.json`](../policies/agent-governance.json) decide the level: workflow-and-permissions and quality-gates are L2, and release-and-publication, credentials-and-sensitive-data and destructive-operations are L1.

## When they apply

Some decisions apply only when the repository gains a certain kind of code:

- [ADR-0012 — svu-derived versions, make bump, and the rolling dev prerelease](https://github.com/frostyard/core/blob/main/docs/adr/0012-svu-versioning-and-rolling-dev-prerelease.md) and [ADR-0053 — Name the svu config file `.svu.yml`](https://github.com/frostyard/core/blob/main/docs/adr/0053-name-the-svu-config-svu-yml.md) — for a released repository: add `.svu.yml` and a `bump` target that runs `svu next`. Does not apply now: this repository has no `go.mod` and no releases; the Worker deploys from `main` with [`deploy.yml`](../.github/workflows/deploy.yml).
- [ADR-0070 — Build tool docs sites with ProperDocs and MaterialX on GitHub Pages](https://github.com/frostyard/core/blob/main/docs/adr/0070-build-tool-docs-sites-with-materialx-on-github-pages.md) — for a user-facing tool: add a `site/` docs site. Does not apply now: this repository is an internal service that the frostyard images call, nobody installs it, and it ships no command or application; its documentation is [`docs/`](README.md).

When you change behavior that one of these ADRs covers, update or supersede the
ADR in frostyard/core first, then change this repository in the same effort.
